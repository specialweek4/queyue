**用户点赞**

前端访问/{blogId}/like，like接口，调用BlogController的like方法，方法接收blogId

在like方法中调用requirePublished(blogId);方法查看博客是否存在/发布

然后调用CounterServiceImpl的like方法，like方法调用toggle方法改变该博客的BitMap，成功的话则写入据聚合桶和脏版本，返回是否修改成功 changed

再调用CounterServiceImpl的getCounts方法方法获取该博客的like计数，返回count

然后用CounterActionResult封装blogid，active(true为已点赞)，changed（是否修改成功），counts（点赞数量）

返回给前端

```java
package com.specialweek.counter.dto;

public record CounterActionResult(

      long blogId,

      boolean active,

      boolean changed,

      long count) {

}

```

前端更新显示实时的计数。


**取消点赞**


前端访问 DELETE /blog/{blogId}/like，调用 BlogController 的 unlike 方法，方法接收 blogId


unlike 方法中先调用 requirePublished(blogId); 方法查看博客是否存在/发布


然后调用 CounterServiceImpl 的 unlike 方法，unlike 调用 toggle 方法把该用户在该博客点赞 BitMap 中对应的位置 0，成功的话则向聚合桶写入 -1、脏版本 +1，返回是否修改成功 changed


再调用 CounterServiceImpl 的 getCounts 方法获取该博客最新的 like 计数，返回 count


然后用 CounterActionResult 封装 blogId，active（false 为已取消点赞），changed（是否修改成功），count（点赞数量）


返回给前端，前端熄灭点赞图标并把计数减一

**查看热门页**


前端访问 GET /blog/hot?current={page}，调用 BlogController 的 queryHotBlog 方法，方法接收 current（页码）和可空的登录态 jwt


queryHotBlog 方法把 jwt 的 subject 解析为当前用户 ID（未登录为 null），然后调用 BlogFeedService 的 getPublicFeed 方法，传入 page、size（每页 10 条）和用户 ID


getPublicFeed 方法先走三级缓存（L2 Caffeine 本地页缓存、L1 热门页 ID 列表、L0 博客片段）拿公共基础页，三层都未命中时回源 MySQL 的 selectHotFeed，并用 singleFlight 锁防止高并发下同一页同时回源造成缓存击穿，回源后回填缓存


拿到基础页后调用 enrich 方法做返回前的计数与用户态覆盖：readCounts 调用 CounterService 的 getCountsBatch 方法一次 pipeline 读取整页 like/fav 实时计数；readFlags 调用 BitmapStateReader 的 getFlagsBatch 方法一次 pipeline 读取当前用户的 isLike/faved；readFollowed 调用 FollowStateService 的 getBatch 方法批量补齐 followed（登录时）


最后组装 FeedPageResponse，queryHotBlog 只取其中的 items 数组返回给前端，前端渲染整页卡片

**查看详情页**


前端访问 GET /blog/detail/{id}，调用 BlogController 的 queryBlogById 方法，方法接收 id 和可空的登录态 jwt


查询到博客后，若是已发布博客，调用 CounterService 的 getCounts 方法覆盖该博客的 liked/favorites 实时计数


登录状态下再调用 BitmapStateReader 的 getFlagsBatch 方法覆盖 isLike/faved，调用 FollowStateService 的 isFollowed 方法覆盖 followed；未登录时三个状态全部置 false

**通用行为接口（知光风格）**


前端访问 POST /api/v1/action/like，body 为 ActionRequest{entityType, entityId}，调用 ActionController 的 like 方法，方法接收请求体和登录态 jwt


like 方法从 jwt 解析出用户 ID，调用 CounterService 的 like(entityType, entityId, uid) 完成位图切换与聚合桶写入，再调用 isLiked 方法实查当前状态，返回 Map 结构 {changed: 是否变化, liked: 当前是否点赞}


unlike、fav、unfav 三个接口流程相同，只是调用的服务方法分别是 CounterService 的 unlike/fav/unfav，返回的第二个字段分别为 liked/faved

@Data
public class ActionRequest {
    @NotBlank
    private String entityType;
    @NotBlank
    private String entityId;
}

**通用计数读取接口**


前端访问 GET /api/v1/counter/{etype}/{eid}?metrics=like,fav，调用 CounterController 的 getCounts 方法，方法接收 etype（实体类型）、eid（实体 ID）和 metrics（指标列表，逗号分隔，可省略）


getCounts 方法先对 metrics 按 CounterSchema 的 SUPPORTED_METRICS 白名单过滤出支持的指标（like/fav），然后调用 CounterService 的 getCounts 方法读取该实体的实时逻辑计数（SDS 快照 + 未刷聚合桶），结构缺失时自动按位图分片 BITCOUNT 重建


最后用 CountsResponse 封装 entityType、entityId、counts 返回给前端


**关注/取消关注**


前端访问 PUT /follow/{id}/{isFollow}，调用 FollowController 的 follow 方法，方法接收 id（目标用户）、isFollow（true 关注 / false 取消）和登录态 jwt


isFollow 为 true 时调用 FollowServiceImpl 的 follow 方法：事务内先校验目标用户存在，insertIgnore 幂等插入关注关系，成功的话在 tb_user_info 上把当前用户 followee +1、目标用户 fans +1，事务提交后调用 FollowStateService 的 setFollowState 方法覆盖关注状态短缓存 qy:state:follow:{userId}:{targetUserId}


isFollow 为 false 时调用 FollowServiceImpl 的 unfollow 方法：事务内 deleteRelation 删除关系，成功的话 followee/fans 各 -1（带大于 0 的保护），事务提交后同样覆盖关注状态短缓存


最后用 FollowActionResponse 封装 targetUserId、following（动作后的状态）、changed（是否真正改变关系）返回给前端，前端据此切换关注按钮并刷新粉丝数

package com.specialweek.follow.dto;

}
